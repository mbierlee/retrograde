The WASM memory allocator: size-class pages + page map

All metadata lives in reserved pages; finding it is pure arithmetic, never a header read.

The heap is carved into fixed 4 KiB logical pages. Small allocations (≤ 2048 B) are rounded up to a size class and become one slot in a page dedicated to that class; larger allocations take a run of whole pages. The central bookkeeping structure is the page map — a flat array, one 20-byte entry per page (24 under MemoryDebug), stored in pages of its own. No header precedes any allocation.

pagesBase = heapStart aligned up to 4 KiB. All metadata (violet) lives in dedicated pages — the page map here, plus slot-bitmap cell pools claimed on demand — never scattered between allocations. Finding any pointer's metadata is one shift and one array read: pageMap[(ptr − pagesBase) >> 12].

2 · Size classes

sizeToClass(n) rounds a request up to the nearest class. Slack within a class is the only per-allocation overhead — roughly 8-byte granularity at the bottom of the table, ~25% geometric steps above 256 B. Every class is a multiple of 8, so returned pointers are always at least 8-byte aligned. The demo below uses the five highlighted classes so the slot grids stay readable.

What an overrun can and cannot damage: the stray byte landed in the next slot's user data (striped) — a real bug, but a contained one. No allocator metadata sits between slots, so the page map is untouched: metrics stay exact, heap walks don't break, no memory becomes unreachable. Under MemoryDebug, a write that runs past the requested size also tramples the slack canary inside the writer's own slot and is reported when that slot is freed.

4 · Pointer inspector — exact validation, no guesswork

Every verdict below is computed from the page map alone, so it is authoritative — there are no magic numbers or checksums to forge, and no way for user data to masquerade as metadata. This is exactly what free, realloc and memmove consult. Enter any offset from pagesBase (0–65535), or use the presets — they pick real addresses from the simulator's current state above.

Interior pointers are resolved, not rejected blindly: the slot start is recomputed with one division, which is what lets memmove bounds-check mid-buffer pointers. The inspected slot is outlined in the simulator above.

propertybehaviour
metadata locationreserved metadata pages (page map + slot-bitmap cell pool); nothing is stored next to an allocation
malloc / free (small)O(1): class → partial page → pop a slot from the free list or the bump pointer
large allocationsfirst-fit over the free-run list; coalescing is O(1) at free time via boundary mirrors
pointer validationexact in every build: range check + page kind + slot-start check + slot bitmap — double frees and interior/foreign pointers are detected, reported and rejected
interior pointersresolved to their allocation in O(1); memmove bounds-checks mid-buffer pointers (class/page-granular in release, byte-exact under MemoryDebug)
alignment≥ 8 bytes, guaranteed (all classes are multiples of 8, pages are 4 KiB-aligned)
metadata overhead~0.5% page map (20 B / 4 KiB page) + 64 B bitmap per small page (~1.6%)
per-allocation overheadclass slack only — 8-byte steps below 128 B, ~25% bounded above
callocalways returns zeroed memory; the memset is skipped only on pages provably still in their memory.grow state (watermark)
