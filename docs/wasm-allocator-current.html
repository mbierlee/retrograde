The current WASM allocator: inline block headers

How source/retrograde/wasm/memory.d manages the heap today — and why its metadata is exposed.

The allocator divides the heap into a chain of variable-size blocks. Every block is a 20-byte MemoryBlock header followed immediately by its data. There is no index or table: the heap is the data structure. To find anything, the allocator starts at the first block and hops from header to header (nextBlock = dataStart + blockSize).

2 · Anatomy of a block header (20 bytes on wasm32)

headerbytes 0–3magic "BLOK"
alloc?4bool
padding5–7—
blockSize8–11capacity
usedSize12–15requested
checksum16–19blockSize ^ "CHEK"
Validity checkisValidBlock() = magic matches and checksum matches. That's it — any 20 bytes that happen to satisfy two XOR-able constants pass. A stale header copy or unlucky user data validates fine.
ReachabilityUser code holding a void* can read the header at ptr − 20, or write it. Nothing is hidden; "internal" is a convention.
Cost20 bytes per allocation. An 8-byte String buffer pays 250% overhead.

block header (allocator metadata) allocated — used bytes allocated — slack (blockSize > usedSize) free block ⚠ corrupted header
What just happened: the user wrote one byte past the end of their own buffer. Because the next block's header starts at exactly dataStart + blockSize, that byte landed on a neighboring "BLOK" magic. Every heap walk — findFreeBlock, coalescing — now stops at the damaged header. Blocks beyond it (greyed out) are unreachable: malloc fails even though free space exists, and the metrics silently undercount.

4 · The structural problems

  • Metadata is adjacent to user data. The most common bug — overrunning your own buffer — lands on allocator state, not on neighboring data.
  • Validation is heuristic. getBlock(ptr) trusts a magic + checksum at ptr − 20; it cannot distinguish a real header from a lucky bit pattern, and cannot resolve interior pointers at all.
  • Allocation is O(heap). First-fit walks the block chain, coalescing as it goes; cost grows with fragmentation.
  • 20-byte tax on every allocation, and returned pointers are only 4-byte aligned by accident of the header size.

The proposed replacement moves all metadata into a reserved region and makes every lookup O(1) arithmetic — see the page-map allocator explainer and the full write-up in todo/redesign-wasm-allocator-size-class-pages.md.
